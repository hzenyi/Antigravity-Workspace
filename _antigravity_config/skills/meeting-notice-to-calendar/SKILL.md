# 會議通知轉 Google 行事曆 (meeting-notice-to-calendar)

## 這個技能做什麼
把「開會通知單」（圖片或文字）自動轉換成 Google 行事曆上的一筆事件，並在事件說明欄完整保留所有會議細節（時間、地點、主席、人員、主題與備忘事項），方便日後回頭查閱不用再翻找紙本或電子公文。

---

## 觸發時機
- 使用者上傳一張開會通知單/會議公告的照片或截圖
- 使用者直接用文字描述一場會議（口述整理、LINE 訊息貼上、公文文字等）
- 使用者明確說「幫我排進行事曆」、「加到日曆」、「建立這場會議的行程」等

---

## 核心工作流程（嚴格遵守：先確認、後新增）

```
[使用者上傳通知單圖片或文字]
               │
               ▼
【1. 讀取與擷取會議欄位】
   • 主旨/主題、開會時間（民國/西元、24h制換算）
   • 開會地點（實體/線上）、主辦單位/主持人/主席
   • 出(列)席人員名單、討論議題/附件重點
   • 差假與排代註記、備註事項、公文字號
               │
               ▼
【2. 檢查缺漏與歧義】
   • 模糊、缺結束時間、地點不完整、行程衝突、多日期版本
   • 🚨 嚴禁猜測！遇上述情況必須先提問澄清
               │
               ▼
【3. 出具「新增內容預覽確認卡」】⭐️【強制暫停點】
   • 完整呈現即將寫入日曆的所有欄位與說明欄文字
   • 說明欄必須完整收錄：時間、地點、主席、人員、主題與備註
   • 多行事曆時提供選擇（預設為使用者自己帳號的主要行事曆）
   • 停在此處，等待使用者確認：「確認」、「OK」或修改指令
               │
               ▼
【4. 使用者明確同意後，正式建立 Google 行事曆事件】
   • 透過原生專屬腳本直接呼叫 Google Calendar API 寫入雲端日曆（無感背景同步）
   • 無需額外產出本機 .ics 檔案，除非使用者主動要求
   • 自動處理 Token 過期刷新機制
   • 回報建立成功結果與 Google 日曆專屬連結
```

### 詳細步驟規範

#### 1. 讀取與擷取會議欄位
- **圖片**：透過多模態視覺能力直接辨識公文與通知單畫面內容（不需外部 OCR 工具）。
- **文字**：直接解析使用者貼上的公文文字或對話訊息。
- **欄位標準化規則**：
  | 欄位 | 說明與轉換規範 |
  |---|---|
  | **主旨/事由** | 會議名稱或討論主題（去除「開會通知單」等雜訊詞，保留核心案名） |
  | **日期** | 正確處理西元或民國年換算（西元年 = 民國年 + 1911，例如 115 年 ➔ 2026 年） |
  | **時間** | 起訖時間（上午/下午制轉 24 小時制；若只給起始時間，需向使用者詢問預計時長） |
  | **地點** | 實體地點（校區、大樓、會議室名稱）或線上會議連結（Google Meet、Webex、Teams 等） |
  | **主辦單位/主持人** | 主辦機關/處室、承辦人姓名與聯絡電話/分機、主席/主持人 |
  | **出列席人員** | 完整擷取處室主管、科主任、召集人、授課教師、行政人員、學生代表等清單 |
  | **討論議題/附件重點** | 開會事由、討論提案、攜帶文件與報告重點條列摘要 |
  | **差假與排代註記** | 記錄公文差假權益（如：准予公假排代、公差、課務自理、差旅費報支） |
  | **備註事項** | 便當、攜帶筆電、簽到注意事項等 |

#### 2. 檢查缺漏與歧義（防錯鐵律）
🚨 以下情況**必須先向使用者提問，確認清楚後才可繼續，禁止用猜測值直接建立**：
1. 日期/時間辨識模糊、圖片字跡不清。
2. 只有起始時間、沒有結束時間或會議時長。
3. 地點資訊不完整（例如只寫「會議室」但沒寫是哪一間、哪個校區、實體還是線上）。
4. 同一時段行事曆上已有其他行程（衝突提醒，主動提示並詢問是否仍要新增）。
5. 文字/圖片中有多個可能的日期或版本（例如通知單上有「原訂」與「更改後」時間、或分梯次開會）。

#### 3. 說明欄（Description）完整收錄標準 ⭐️【核心規則】
**會議細節必須完整寫入行事曆說明欄**，格式規範如下：
```text
【會議時間】民國 115 年 9 月 9 日（三）12:00 - 13:00（西元 2026-09-09）
【會議地點】教學暨行政大樓二樓會議室
【主　　席】廖校長鴻銘
【主辦單位】教務處（承辦人：XXX，分機：XXX）

【會議主題與議題】
1. 115學年度第一學期拔尖計畫執行運作與時程討論。

【出(列)席人員】
• 處室主管：黃主任正誼、陳組長姚萍
• 授課教師：陳崇彥老師、黃宜弘老師、盧佳信老師、劉冠辰主任、李承弦老師、余能義老師、陳怡誠老師
• 行政人員：林育瑜小姐、鄭羽鈞小姐 工讀生

【注意事項與備忘】
※ 備有便當。
※ 公文字號/差假註記：准予公假排代
```

#### 4. 出具「新增內容預覽確認卡」（強制審查點）
在正式向 Google 日曆發出建立請求前，必須先輸出包含完整細節之預覽卡片，供使用者核對：
- 📌 事件標題
- 🗓️ 會議時間
- 📍 會議地點
- 📅 寫入行事曆（預設為使用者自己帳號的主要行事曆，可指定切換）
- 🔔 預設提醒（前 15 分鐘、前 1 天）
- 📝 完整說明欄預覽（含時間、地點、主席、人員、主題與備忘）

#### 5. 使用者確認後，正式建立 Google 行事曆事件
- **嚴格等待**：必須收到使用者明確的「確定」、「OK」、「新增」或確認指示後，才能執行新增。
- **目標行事曆選擇**：
  - 預設寫入「使用者自己帳號的主要行事曆 (`primary`)」。
  - 若使用者回覆指定其他行事曆（如教務處公務日曆），則寫入指定日曆。
- **執行直寫腳本**：
  - 使用內建腳本：`node .agents/skills/meeting-notice-to-calendar/scripts/add_calendar_event.js "<JSON payload>"`
  - 該腳本會讀取 `~/.config/google-calendar-mcp/` 下的金鑰與 tokens，並在 Access Token 過期時自動用 Refresh Token 刷新換證。
  - **預設不產出本機 `.ics` 檔案**，維持工作區極簡乾淨。

#### 6. 回報結果
建立完成後，清楚回報：
- 📌 會議標題
- 🗓️ 日期時間
- 📍 地點
- 📅 已寫入之行事曆名稱
- 🔗 Google 行事曆事件專屬網頁連結（點擊可直接在日曆檢視）
