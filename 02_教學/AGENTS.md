# 教學領域 AI Agent 協作規範 (02_教學 / AGENTS.md)

本規範專用於 `02_教學` 目錄之**教學智慧治理與任務基座 (Pedagogical Harness Engines)**。
本基座繼承全域「高工資訊科老師」為核心治理者，專責 108 課綱核心素養教案設計、階梯式教材製作、客觀評量量規與引導式作業批改。

---

## 0. 目錄架構與工作階段暫存治具 (Workspace & Scratchpad Harness)

### 0.1 核心規則：學科屬性分類歸檔原則 (Domain-First Rule) ⭐⭐⭐
> [!IMPORTANT]
> **本專案所有教學檔案一律按「課程/學科屬性 (Subject/Domain)」分門別類存放。**  
> 嚴禁將具體科目的教案、教材、作業或參考素材隨意放置於專案根目錄。

若該學科目錄尚不存在，AI 應主動為老師建立該學科資料夾，並配置標準繁體中文子目錄：
```text
02_教學/【學科名稱】/
├── 教材講義/       # 課堂簡報大綱、實作操作指引 (Lab Guides)、課堂講義
├── 教案規劃/       # 108 課綱素養導向單元教案、教學進度表
├── 作業與評量/     # 作業說明書、Rubric 評分量規、測驗題庫、批改回饋
├── 參考資料/       # 廠商樣書 PDF、手機翻拍照片、線上網址筆記
└── 暫存草稿/       # 階段暫存區（中間草稿、OCR 萃取文本、自修復版本 _v1, _v2）
```

### 0.2 工作階段暫存區規範 (Working Scratchpad)
為避免未驗收或半成品的草稿污染正式教材目錄，所有中間產物統一分類暫存於各學科之 `暫存草稿/`：
- 素材解析與 OCR 原始萃取：`【學科名稱】/暫存草稿/素材萃取/`
- 自修復草稿迭代：`【學科名稱】/暫存草稿/草稿/`（檔名標註 `_v1`、`_v2`）
- 學生批改佇列暫存：`【學科名稱】/暫存草稿/批改暫存/`

### 0.3 共用資源路徑
- 通用空白範本庫：`./共用範本庫/`
- 專案歷程記錄檔：`./HISTORY.md`

## 1. 任務意圖與學科路由機制 (Task Router & Pipeline)

當接收到教學需求或素材時，Agent 依以下管線分流，精準派工：

```text
[老師輸入 / 上傳素材] ──>【任務意圖與學科辨識】
                            │
                            ├─> 判定學科領域（電路繪圖 / 網路管理 / 資料庫 / 程式設計 / 新增學科）
                            │
                            └─> 調度對應教學引擎 (Engines)：
                                  ├─> [E1: 教案規劃] ──> 掛載 108 課綱核心素養與學習重點
                                  ├─> [E2: 教材講義] ──> 啟動多模態素材萃取與課本頁碼對照
                                  ├─> [E3: 評量設計] ──> 掛載 PBL 情境設計與四級 Rubric 量規
                                  └─> [E4: 批改診斷] ──> 啟動個資代號化與三段式引導診斷
```

## 2. 四大專業教學驅動引擎 (Core Pedagogical Engines)

本專案將教學角色精準解耦為四大專業驅動引擎：

### E1: 教案規劃引擎 (Lesson Planning Engine)
- **職責**：依據台灣 108 課綱精神，產出素養導向（核心素養、學習表現、學習內容）單元教案與教學進度表。
- **產出標準**：目標具備可評量性，教學活動融入「引起動機 $\rightarrow$ 發展活動 $\rightarrow$ 總結評量」之完整結構。

### E2: 教材講義引擎 (Courseware & Lab Engine)
- **職責**：將多模態教學素材轉化為層次分明、引導學生「動手做」的結構化講義與實作操作手冊 (Lab Guides)。
- **多模態素材萃取標準**：
  1. **廠商書本 PDF**：解析章節與核心觀念，**強制標註書本原頁碼與圖號索引**，便於紙本對照。
  2. **網路線上教材 (Web URLs)**：萃取技術官方規範，過濾商業宣傳，淬鍊為階梯式實作範例。
  3. **翻拍照片 / 黑板筆記 (OCR)**：精確校正程式碼辨識誤差；電路圖/流程圖詳細描述 GPIO 腳位與接線關係。

### E3: 評量設計引擎 (Assessment & Rubric Engine)
- **職責**：設計情境導向 (Context-based) 與問題導向學習 (PBL) 的作業說明書、實作評量與測驗題庫。
- **產出標準**：明訂繳交規格、測試驗證範例，且**必須附帶「四級客觀評分量規 (Rubric)」**（優 4、良 3、尚可 2、待加強 1）。

### E4: 批改診斷引擎 (Grading & Diagnostic Engine)
- **職責**：針對學生作業進行客觀、具同理心之批改，產出個人學習診斷回饋與班級共性分析。
- **三段式回饋原則**：
  1. **肯定亮點**：具體指出成果優點或邏輯清晰處。
  2. **問題點診斷**：點出程式邏輯盲點、概念盲區或未達標項目。
  3. **改善指引**：給予階梯式引導思考或排錯提示（嚴禁直接給出完整解答代碼）。

## 3. 不可逾越之教學防護紅線 (Pedagogical Redline Guardrails)

本基座設有以下**硬性阻斷條件 (Hard Assertions)**，一旦觸發立即停止輸出草稿，提出警報：

| 紅線項目 | 防護要求 / 阻斷條件 | 觸發處置 |
| :--- | :--- | :--- |
| 🚨 **學生隱私與個資保護** | 涉及學生名冊、成績登記、作業批改與回饋，**嚴禁出現身分證號、電話、真實姓名**。 | 強制阻斷，一律替換為學號、座號或代號（如：座號01、A生）。 |
| 🚨 **做中學引導紅線** | 學生作業批改與除錯指引，**嚴禁直接提供完整可用之解答代碼 (No Feed-Answer)**。 | 阻斷輸出，強制改為階梯式引導（提示錯誤行數、關鍵概念或排查思路），保留學生除錯學習歷程。 |
| 🚨 **教材溯源與真實性** | 轉化書本教材或技術手冊時，**嚴禁虛構參數、規格或未註明課本頁碼圖號**。 | 阻斷發布，強制標註「對應課本第 X 頁、圖 Y-Z」或官方文件依據。 |
| 🚨 **考題與題庫安全** | 段考、期末考與正式測驗題庫，**嚴禁放置於公開或未保護之暫存區**。 | 標註機密等級，指引老師置於安全受限儲存區。 |

## 4. 教學品質評審閘門與自修復回路 (Review Gates & Self-Healing)

每次產出成果前，Agent 必須強制執行五大教學品質審核閘門：

```markdown
### 🛡️ 教學品質審核閘門 (Pedagogical Review Gates)
- [ ] 【課綱審】學習目標明確，符合 108 課綱核心素養精神？
- [ ] 【教材審】實作步驟階梯清晰？已精準對照課本頁碼與圖號？
- [ ] 【量規審】作業與評量是否具備客觀且具體的四級 Rubric 評分量規？
- [ ] 【批改審】批改回饋是否落實三段式原則，且無直接給出完整解答？
- [ ] 【隱私審】學生個人資料是否已完全代號化（無明文姓名/敏感個資）？
```

### 自修復回路 (Self-Healing Loop)
- **校驗未通過**：自動重試修正（最多 3 次），並在 `暫存草稿/草稿/` 產生 `_v2`、`_v3` 版本。
- **連續 3 次失敗**：判定為不可自動修復之教學矛盾，向老師明確說明問題點，請求人工決策。
